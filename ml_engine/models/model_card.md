# Model Card: DevMentor AI Error Classifier (v1.1)

## Overview

Classifies a sanitized Python error into one of 12 categories so the widget can show a matching plain-English explanation.

- **Input:** `"{error_type} {sanitized message}"`, for example `KeyError 'email'`
- **Output:** a category plus a calibrated confidence
- **Model:** TF-IDF (1-2 grams, max 5000 features) + Linear SVM wrapped in `CalibratedClassifierCV` (cv=2)
- **Files:** `classifier.joblib`, `vectorizer.joblib`. Rebuild with `python ml_engine/train.py`.

## Labels

syntax_error, type_error, none_type_error, key_error, index_error, attribute_error, module_not_found, file_not_found, permission_error, value_error, network_error, other_error (catch-all).

## Training Data

132 labelled examples generated by running small failing Python snippets and sanitizing the output. No real user errors or scraped tracebacks.

| Category | Rows | Category | Rows |
|---|---|---|---|
| type_error | 22 | syntax_error | 10 |
| attribute_error | 19 | module_not_found | 5 |
| other_error | 19 | file_not_found | 5 |
| value_error | 17 | network_error | 5 |
| key_error | 12 | index_error | 3 |
| none_type_error | 12 | permission_error | 3 |

- Exact duplicates are capped at 3 copies.
- The 5 network_error rows are hardcoded, because live network calls gave different output between runs.
- Rebuilding gives a byte-identical `dataset.csv`.

## Evaluation 1: generated data (in-distribution)

3-fold stratified cross-validation over all 132 rows.

| Model | Macro F1 |
|---|---|
| Logistic Regression | 0.801 |
| Linear SVM | 0.957 |
| **Linear SVM, calibrated (used)** | **0.931** |
| Multinomial Naive Bayes | 0.661 |

This number is optimistic: the test data comes from the same generator as the training data.

## Evaluation 2: real-world errors (dev set)

Collected from public GitHub issues, sanitized, then labeled by hand using written rules (`ml_engine/data/eval/LABELING_RULES.md`). Rows that also appear in the training data are removed.

| | Rows | ML only (macro F1) | ML + rules (macro F1) |
|---|---|---|---|
| First run (8 overlap rows still included) | 245 | 0.776 | 0.863 |
| **Baseline after removing overlap (v1.1)** | 237 | 0.773 | 0.875 |

Ambiguous subset (OSError, TimeoutError, ImportError, RuntimeError, Exception, AssertionError, plus all other_error and none_type_error rows), end-to-end: 52 rows, accuracy 0.808. Macro F1 is not reported for this subset, because most categories appear only once or twice in it, which makes the macro average misleading (the script printed 0.299).

Findings from the first run:
- The rules fallback is worth about 9 macro F1 points over ML alone, and 39% of real errors were routed to it.
- The model over-predicts `other_error` on unfamiliar wording (precision 0.34, recall 0.96).
- Weakest categories end-to-end: network_error (F1 0.52), none_type_error (0.83), syntax_error (0.80).
- Cause: training data has only 5 `ConnectTimeout` network rows and no IndentationError, so real exception names like `MaxRetryError` are unseen.

Real-world performance is about 7 macro F1 points below the generated-data figure before the overlap fix. Use the real-world numbers when describing the model.

## How It Is Used

If confidence is at least 0.6 (`settings.json`), the ML category is used. Otherwise a rules mapping on the exception name decides. In optional `local_llm` mode, `other_error` or confidence below 0.7 also triggers a local Ollama explanation, labelled as AI-generated.

Before the model runs, `assess_risk()` checks the sanitized message. If flagged, the error is shown only in the terminal and never sent to the service.

## Limitations

- **Python only**, and only 12 categories. The real data has a long tail (framework-specific errors) that lands in `other_error`.
- **The exception type is in the input**, so easy categories score well partly for that reason. The informative cases are none_type_error, network_error and other_error.
- **Small training set** (132 rows); several categories have 3-5 examples.
- **Small eval set**: index_error has 9 rows, so its score moves a lot per prediction.
- **The eval set is now a dev set.** It has informed decisions, so it is not an unbiased test. A fresh batch is needed for a final number.
- **Labels follow written rules** (for example ImportError split by cause), so scores depend on those choices.
- **Risk gate gap:** `assess_risk()` only flags 16+ character runs containing a digit. A 16-19 letter secret with no digits passes both it and `sanitize_tokens()` (20+).
- **Sanitizer coverage:** IPv4 addresses (except 127.0.0.1) are now redacted. Hostnames, usernames and IPv6 are not.

## Planned (v2)

Language-agnostic cause taxonomy discovered from clustering real errors, slot-filled and code-based explanations, a parser per language/tool, more real training data, and a fresh held-out test set per language.
