# Model Card: DevMentor AI Error Classifier

## Overview

Classifies a sanitized Python error into one of 12 categories so the widget can show a matching plain-English explanation.

- **Input:** `"{error_type} {sanitized message}"`, for example `KeyError 'email'`
- **Output:** a category plus a calibrated confidence
- **Model:** TF-IDF (1-2 grams, max 5000 features) + Linear SVM wrapped in `CalibratedClassifierCV` (cv=2)
- **Files:** `classifier.joblib`, `vectorizer.joblib`. Rebuild with `python ml_engine/train.py`.

## Labels

syntax_error, type_error, none_type_error, key_error, index_error, attribute_error, module_not_found, file_not_found, permission_error, value_error, network_error, other_error (catch-all for exceptions that fit nowhere else).

## Training Data

132 labelled examples, generated by running small failing Python snippets and sanitizing the output. No real user errors or scraped tracebacks.

| Category | Rows | Category | Rows |
|---|---|---|---|
| type_error | 22 | syntax_error | 10 |
| attribute_error | 19 | module_not_found | 5 |
| other_error | 19 | file_not_found | 5 |
| value_error | 17 | network_error | 5 |
| key_error | 12 | index_error | 3 |
| none_type_error | 12 | permission_error | 3 |

- Exact duplicates are capped at 3 copies. Duplicates add no TF-IDF signal.
- index_error and permission_error are small on purpose: Python produces essentially one message for each.
- The 5 network_error rows are hardcoded, because live network calls gave different output between runs.
- The dataset is reproducible: rebuilding it gives a byte-identical `dataset.csv`.

## Evaluation

3-fold stratified cross-validation over all 132 rows. A held-out 10% test set covered only 7 of 12 categories, so it was rejected.

| Model | Macro F1 |
|---|---|
| Logistic Regression | 0.801 |
| Linear SVM | 0.957 |
| **Linear SVM, calibrated (used)** | **0.931** |
| Multinomial Naive Bayes | 0.661 |

A single 80/20 split of the final model gave 0.94 macro F1 and 0.93 accuracy on 27 rows. With 1-5 test rows per category it is noisy, so the CV figure is the one to rely on.

Calibration costs about 2.6 points of macro F1 and provides the probabilities that confidence routing needs.

**Strong (F1 1.00 in CV):** file_not_found, index_error, key_error, module_not_found, network_error, permission_error, syntax_error.

**Weak:**
- none_type_error: only 5 of 12 correct in CV. NoneType errors reuse the attribute_error and type_error message templates.
- type_error: confused with none_type_error.
- other_error: 16 of 19 correct.

## How It Is Used

If confidence is at least 0.6 (`settings.json`), the ML category is used. Otherwise a rules mapping on the exception name decides. In optional `local_llm` mode, `other_error` or confidence below 0.7 also triggers a local Ollama explanation, labelled as AI-generated.

## Limitations

- **Generated, not real-world data.** Real tracebacks are messier, so real accuracy is likely lower.
- **The exception type is in the input.** For most categories it nearly determines the label, so scores overstate what the model learns from message text. The genuinely hard cases are none_type_error versus type_error and attribute_error.
- **Small dataset.** Several categories have 3-5 examples, and scores there move a lot when a single prediction flips.
- **Python only.** No other languages yet.
- **Sanitization first.** The model only sees sanitized text, which removes paths, emails, tokens and similar details.
- **Unseen exception types** tend to land in other_error at moderate confidence (e.g. ConnectionResetError at 0.55) and then use the rules fallback.

## Planned (v2)

A real-world traceback dataset with a hand-labelled holdout set, multi-language support, and per-language models.
